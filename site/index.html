GPU tensors become pixels without ever touching the CPU — byte-exact on Metal and Vulkan.

Caliper is a native C++ framework for watching a neural network, computing its graphics straight from the tensors in VRAM.

Every other tool copies tensors off the GPU and back again to draw them. Caliper never leaves the GPU, and proves the result pixel-exact against a CPU reference on Apple Silicon and Windows/NVIDIA.

The round trip everyone else takes

A model's internal state — weights, activations, embeddings — lives in GPU memory. To look at it, the usual tools copy it to the CPU and hand it to a plotting stack: matplotlib rasterizes a figure to a PNG, or TensorBoard writes an event file that a web server polls, a browser decodes, and a GPU re-uploads to display. Two bus crossings, one filesystem, seconds of latency — for data that started on the same class of chip that draws your screen. So researchers sample sparsely, every N minutes or every epoch, and whole categories of fast dynamics — the first two hundred optimizer steps, how a representation reorganizes during a loss spike — are simply never seen.

Caliper derives the view on the GPU and draws it there with Dear ImGui and ImPlot — immediate-mode GPU libraries that read the tensor in place, with no PNG, no event file, and no browser in between. Dense image and geometry views never leave the GPU; only the small coordinate arrays behind curves and scatters still cross to the CPU, as kilobytes.

How it works

Zero-copy means something different on each GPU architecture — a pointer cast under Apple Silicon's unified memory, external-memory interop on Windows/NVIDIA — but the applet code is identical on both.

Apple Silicon (Metal / MPS)

Unified memory means CPU and GPU share one pool of physical RAM, so a PyTorch MPS tensor's storage already is an MTLBuffer — the object Metal renders from. The handoff is a pointer cast plus safety rules: the frozen struct has no storage-offset channel, so the adapter rejects non-contiguous tensors and views rather than silently addressing the wrong texels. Zero host copies, one on-GPU blit.

Windows/NVIDIA (Vulkan / CUDA)

Discrete GPUs separate VRAM from system RAM, so zero-copy means keep the data in VRAM and make both APIs share the allocation. The renderer exports (Vulkan external memory, opaque Win32 handle) and CUDA imports — because torch's caching allocator can't export. Device pairing is UUID-driven; a hybrid-GPU mismatch disables interop rather than corrupting. CUDA VMM blocks pad up to the driver's ~2 MiB allocation granularity, so bounds are derived from the padded size, not the tensor's. Synchronization is GPU-ordered by a shared timeline semaphore — no CPU thread waits on the hot path.
