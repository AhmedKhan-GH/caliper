## The GPU (CALIPER_GFX_CMAP_BENCH=1 caliper_gfx_tests --test-case="gfx/Metal colormap: timing*")

Each sample is one command buffer of 16 dispatches of one pass over an f32 heatmap into an rgba8unorm
texture, GPU time (GPUEndTime - GPUStartTime) / 16; the passes take turns, 40 samples each after 5 warm-up
rounds. The integer pass is the generated colormap_texture as the layer compiles it (safe math, 8 x 8);
the float pass is the Metal renderer's cmap_f32 copied into the test and compiled as the renderer compiles it
(default options, which are fast math, 16 x 16). The other rows edit the MSL text to attribute the
difference; the two marked "not exact" drop steps of the decision and only time what is left. The fields
are over (0, 1) with viridis; on both, the float guess is confirmed by its first two comparisons for every
texel (a CPU count with colormap_keys.h over the 2,048 x 2,048 fields), so the neighbour tries and the
binary search never run.

## What the numbers say

| Heatmap | Float pass | Integer pass (as the layer compiles it) | Difference | Threshold (5 % or 20 µs) |
|---|---|---|---|---|
| 1,024², smooth field | 9.5 µs | 31.0 µs | +21.6 µs, 3.3x | exceeded |
| 1,024², uniform random values | 8.3 µs | 26.4 µs | +18.1 µs, 3.2x | within 20 µs, not within 5 % |
| 2,048², smooth field | 25.8 µs | 79.2 µs | +53.4 µs, 3.1x | exceeded |
| 2,048², uniform random values | 28.9 µs | 79.3 µs | +50.4 µs, 2.7x | exceeded |

Where the extra time goes, at 1,024² on the smooth field (2,048² in brackets):
- Safe math, that is the precise division of the float guess: 13.2 µs (33.5 µs). With fast math the integer
  pass takes 17.8 µs (45.7 µs); the float pass with safe math takes 22.6 µs (57.3 µs). The decision's
  exactness does not rest on the guess, and caliper_shader_tests already checks the probe byte-exact with
  fast math on and off.
- The keys and the table read as components of uint4 arrays at a dynamic index: 3.5 µs (9.4 µs); flat u32
  arrays take 27.5 µs (69.8 µs). Reading the table from constant rather than device memory costs nothing on the
  float pass, and moving the whole block to device memory changes nothing.
- The two integer comparisons of the guess: 4.1 µs (10.7 µs) over the guess and the table load alone.
- The neighbour tries and the binary search, which never run on these fields, still cost 3.3 µs (8.8 µs) by
  their presence in the code.
- The workgroup shape costs nothing: 16 x 16 takes the same time as 8 x 8.

A cheaper form that keeps the decision exact: fast math, flat key and table arrays and a 16 x 16 workgroup
take 14.7 µs at 1,024² (1.56x the float pass, +5.3 µs) and 36.3 µs at 2,048² (1.41x, +10.6 µs), within the
20 µs clause at both sizes but not within 5 %. WGSL gives a uniform array a 16-byte stride, so flat keys need
the block's keys as a storage buffer (compute only, since a compatibility-mode vertex stage reads no storage)
or as an r32uint texture (textureLoad, any stage), or an MSL-only layout; and the layer would compile the
colormap programs with fast math. Moving the rare paths out of line is not measured.

The share of a frame: step 0's baseline measured, for a 1,024² heatmap in the viewer, an update of 13.4 µs and
a frame of 24.1 µs of GPU time (2,048²: 63.9 µs and 47.5 µs). The kernel-level difference above adds about
21.6 µs to the first (58 % more GPU time per frame, the colormap from about a quarter of it to about half) and
53.4 µs to the second (48 % more); against the 16.7 ms of a 60 Hz frame it is 0.13 % and 0.32 %.

## The decision, and the built form re-measured (2026-11-16, 01:42, load 3.93)

The decision is: keys everywhere, in the cheaper exact form, with the threshold read as 20 µs
absolute; the float formula is retired on the native path when the texture path moves (step 8). The built form
differs from the edited-MSL variant above in two ways, each measured first in a scratch probe:
- The block is one 16-byte entry per level (its first key, the next level's first key, its colour; 4,112
  bytes) instead of flat u32 arrays, which WGSL does not allow in a uniform (its arrays there have a 16-byte
  stride). A level test and the level's colour are then one load; in the probe, at load 22, it took 10.7 µs
  against 11.8 µs for flat arrays at 1,024² and 27.2 µs against 36.4 µs at 2,048².
- The workgroup is 16 x 8, not 16 x 16: compatibility mode allows 128 invocations by default, and the browser
  rows refused 256 there. On Metal the shape changed nothing (8 x 8 and 16 x 16 above).
Fast math is a per-program option of the layer (ProgramDesc::fast_math, "fast_math" in the manifest), set only
for colormap_texture.
